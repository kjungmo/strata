# NUMBERS.md: every quantitative claim and where it comes from

Results live in `paper/experiments/results/` (written by `bash paper/experiments/run_all.sh`).
Tables `tables/*.tex`, `tables/e4_text.tex` (the E4 sentences), `figures/data/*.dat` and `figures/e4_cost.tex` are generated by
`tools/make_artifacts.py` from those files; no number in them is hand-typed. The sequential-test and real-data parts (Sections 4, 6
and 7, the sprt arm and E7 in Section 5) are generated by `tools/make_v2_artifacts.py`, which `make_artifacts.py` runs. It reads
`results/*.csv`, `realdata/results_p1/`, `results_p1b/`, `results_p2/`, `results_p3/` (JSON, TSV, text), the library defaults
(`strata_core/include/strata_core/layered_map.hpp`) and `PREREG.md`, and writes the tables `e7_oc`, `e7_autocorr`, `sprt_arm`, `e3_sprt`,
`p1b_gates`, `p1b_gap`, `p1b_optionc`, `p3_lil`, `p3_lil_wall`, `p3_spires`, `p3_agree`, `p3_kth`, `p3_veto` and `tables/numbers_v2.tex`.
`numbers_v2.tex` is a list of `\newcommand` lines; each ends with a comment that names the file and field of its value. **The prose of
those sections holds no hand-typed measured number: every such number is one of these macros**, so the numeral check never sees it, and the
check of `numbers_v2.tex` (below, item 5) replaces it.

## What `number_guard.py` checks (and what it does not)

`python3 paper/experiments/number_guard.py` (CI job `paper`):

1. regenerates every generated file and compares it with the committed one;
2. recomputes the quoted results from the CSVs and the code and requires the resulting phrases in the text;
3. compares the git tree ids of `strata_core/`, `strata/` and `scripts/` with those of commit `708d62f`, and fails on uncommitted
   changes in them;
4. locates **every numeral** of the hand-written sources (`sections/*.tex`, captions of the hand-written figures) and requires it
   to be tied to a recomputed value or to be listed as structural. Counts at the last run:

5. (`guard_v2`) checks every macro of `numbers_v2.tex` against a second source and enforces the wording rails:
   - every `Pt...` macro (real-data evaluation) is a number of the generated `P3_REPORT.md` (made from the JSON files by
     `make_report_p3.py`) or of its hand-written summary; the derived ones (two quotients, the counts of the failed runs, the wall-run counts of the SPRT arm, the three numbers of the memory probe of Amendment 1) are listed with the reason and checked against the JSON files or `PREREG_P3.md`;
   - every `Cal...` macro (calibration) is a number of `P1B_REPORT.md`, `PREREG.md`, the P2 replay or the Keble height record;
   - the sequential-test macros are recomputed here: the increments of the first release give `SqLegMzero` and `SqLegMone`;
     Ville's bound `exp(-A)` equals `alpha / (1 - beta)`; the two expectations of Proposition `prop:ville` are checked at several
     hit rates; the leak ratio of Proposition `prop:leak` is recomputed; the Wald column of `e7_oc.csv` is recomputed from the closed form;
     and the exact column is recomputed by an independent lattice computation (rates 0.05, 0.2, m*, 0.5, 0.7, 0.9; both rules);
   - the wording rails of the lead: provisional pair, nothing froze, not calibrated for 3D, Periodic not validated on real data,
     realised rates above nominal, memory failures, single-pass KTH, no truth in Boreas, no winner, demotion CUSUM-like, the bound
     for the first test of a history, the zero-drift limit `-B/(A-B)`, amendment after the first calibration measurement, memory unbounded,
     the node not in the loop of the real-data runs; and the forbidden phrases (`is below the bound`, `is within the bound`,
     `was frozen`, `the best rule`, `outperform`, `with the same error rates`, `ever graduates`, `we did not measure it`,
     `calibrated periodic`, `times the bound`) are absent.

Limits, stated plainly:

- *Structural* numerals are not recomputed. They are locked: `structural_numerals.tsv` lists each one in order (file, value,
  preceding text, reason), and the guard fails when the list and the text differ. `--update-lock` rewrites the list; the change then
  shows in the diff. This covers the scenario sizes of §4.1 and the design constants written as symbol = value, which are restated by
  hand from the harness sources.
- A numeral that is tied to a source only by value ("bare number") can be exchanged for another recomputed value of the same file
  without the guard noticing.
- `main.tex` (title, author line) is not scanned.
- `paper/experiments/mutation_check.py` changes every numeral in turn and reports the ones the guard misses; the last report is
  `paper/experiments/mutation_report.txt`.
- The Markdown companion is checked for the presence of the recomputed phrases only (step 2), not numeral by numeral.

**Code pin.** The paper is pinned to `strata_core/`, `strata/` and `scripts/` at commit `708d62f` (`a7559d4` added the evidence model `sprt`; `5c20bba` and `708d62f` changed only node status text and YAML comments; the first release of the manuscript pinned `312b09c`, no tag; first code release (v0.1.0) `a82f935`). E0–E3, E5, E6 (both arms) and E7 reproduce their
committed CSVs byte for byte (`check_reproduction.sh`; compilers in `paper/experiments/reproduction_log.txt`). Under libc++ seven
of the 39 seeded files differ: four of 19 in the legacy arm and three of 20 in the sprt arm and E7, `e4_cells_sprt.csv` among them
(`check_stdlib.sh`, record in `results/stdlib_libcxx/summary.txt`).

**E4 timings.** Recorded only with `paper/experiments/measure_e4.sh` on a quiet host (rules in the script). The paper uses a
latency or a ratio only if at least three valid recordings exist and their backend ratios agree within 20 % at every extent;
otherwise it reports the direction and the exact cell counts (`tools/make_artifacts.py`, section E4). Every earlier timing file,
all taken on a loaded host, is kept in `results/e4_exploratory/` with an index.

**Centring fix (2026-09-28).** All E1–E3 results are from the corrected engine
(centred FreMEn coefficients, branch `fix/periodicity-centering`). The same harness
built against the v0.1.0 `strata_core` wrote `results/pre_fix_2026-09-28/`; its
periodicity-off E1/E3 and 64-window E2 files are byte-identical to the results committed
before the fix. E4 was not rerun: it runs with periodicity off, a path the fix does
not change.

**Calibrated periodic test (2026-09-28, second pass).** The engine now adds a noise-calibrated
significance test (Proposition `prop:chernoff`, nominal level δ = `periodic_false_alarm` = 0.1).
δ was chosen by E0 (`src/e0_calibration.cpp`) on seeds 20260928+, disjoint from the E1–E4 seeds
(12345 + offsets in [0, 1500]); no evaluation seed was used for tuning. The centred engine's
results before this change are archived in `results/pre_calibration_2026-09-28/`. E1 CSVs are
byte-identical after the change (the wall is constant, d = 0); E2 and E3 (periodicity on) were
rerun; E4 was not rerun (periodicity off, code path unchanged).

**Alpha spending (2026-09-28, third pass).** The shipped rule spends δ over the touch count,
δ_n = δ·T/(n(n+1)) (Proposition `prop:spend`, `PeriodicityModel::spentLevel`,
`periodic_alpha_spending = true`), and δ = 0.2 was chosen by the calibration half of E5
(`src/e5_trajectory.cpp`, seeds 30260928+) before its evaluation half ran (seeds 40260928+).
Both ranges are disjoint from E0 (20260928 + offsets < 10000), E1–E4 (12345 + [0, 1500]) and
the unit tests (800000–852000). The engine with the single-read-out level (δ = 0.1) wrote
`results/pre_spending_2026-09-28/` (E1 periodic, E2, E3 periodic). After the change E0 (which
now selects the single-read-out rule explicitly), E1 and the 64-window E2 files are
byte-identical; the E2 sweep and E3 periodic were rerun; E4 was not rerun.
