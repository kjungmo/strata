\section{Discussion and Limitations}\label{sec:disc}

\noindent\textbf{What the evidence shows about the test.} The synthetic evidence supports three statements. The increments of the first release are a sequential probability ratio test whose hypotheses were implied, not chosen (Section~\ref{subsec:seqv01}); the operating characteristic of the test of version 0.2 on the real engine matches the exact computation of the rule and is approximated by Wald's closed form, and its error bound holds under independent windows (E7); and the same bound is inflated by autocorrelated windows (Table~\ref{tab:e7ac}). The real-data evidence supports a narrower statement: on LILocBench clutter the sequential test graduates fewer cells than the rules of the first release, at the price of a longer wait to graduate walls and of more Undecided structure on Spires, and the realised per-cell rate is above the nominal per-history level. It does not support a statement that the sequential test is the better map: the compared rows differ on different measures in different directions, and each dataset leaves one measure out (Section~\ref{subsec:p3cannot}).

\noindent\textbf{Why the realised rate is above the nominal level.} Three things differ between the bound and the table. The unit differs: the bound is per history, the table counts cells, and a rejected cell starts a new history. The windows are autocorrelated, and E7 shows the direction of that effect. The clutter class is not pure: moved furniture and lingering people have a hit rate above $m_0$, and no hit-rate test tells them from a wall. We did not separate the three contributions on the real data, so the factor between the realised and the nominal rate is not explained.

\noindent\textbf{What the evidence shows about the backends.} Across E1--E4 the two backends behave as one engine wearing two geometries. E1's near-identical F1 trajectories and E4's live-cell counts are the empirical face of \eqref{eq:objective}: \code{LayeredMap} and \code{PeriodicityModel}, exercised directly in E2 and E3, never see which backend produced the id they update. The backends diverge in two places, the high-clutter precision gap and the per-call cost. Both runs execute the same classifier code on differently sampled input; neither difference was isolated to one mechanism.

\noindent\textbf{Cost Analysis.} The window update is linear in the number of live cells (\S\ref{subsec:classify}), so cost is governed by how many cells a backend creates. The flat voxel hash is the source of \code{voxel3d}'s 4.4--10.0$\times$ larger live-cell count: every sampled free voxel becomes its own entry, at an estimated 56~B with periodicity off, with no spatial compression. OctoMap \citep{hornung2013octomap} and UFOMap \citep{duberg2020ufomap} collapse coherent free or occupied regions into single octree nodes and would scale better to very large, sparsely occupied 3D extents. We accept the trade for $O(1)$ insert and lookup and a backend simple enough to unit-test without ROS. The largest synthetic configuration (E4) is estimated at 37.0~MB; this is the synthetic estimate at 56~B per live cell with periodicity off, not a measurement, and the real-data runs need far more (below). Warning: memory grows with the cells touched. Undecided cells are kept, and nothing is forgotten out of view (Remark~\ref{rem:fov}), so over a lifelong run memory is unbounded.

\noindent\textbf{Forgetting outside the field of view.} Remark~\ref{rem:fov} is an operational limitation, not a footnote. Decay runs only inside the touched branch, so a transient object that accumulates strong evidence and then leaves sensor coverage for good---a box dragged into a corridor the robot no longer visits---keeps its evidence indefinitely. Forgetting in \sname\ is coupled to re-observation, not to elapsed time. In a bounded, frequently re-swept environment, the setting E1--E4 implicitly assume, this rarely matters; in a sparsely revisited one it is a real failure mode that the current code does not address.

\noindent\textbf{Free space is remembered.} The same coupling shows in \code{grid2d}'s free value. A cell that a ray has cleared reads free while its last observation was free and no Periodic, Static or occupied-leaning Transient class claims it, so free means last observed free, not currently free. An obstacle that appears where the sensor no longer looks reads free until it is observed; from its first hit it reads 50, out of view too, until a ray observes the cell free again. Free space is also carved only along beams that return a hit inside the array (\S\ref{subsec:keying}): a beam without a return, or one that ends beyond the array, clears nothing, so open space bounded only by such beams stays Unknown, and occupied evidence along them is never contradicted. A map smaller than the sensor's range therefore keeps cells that a model clearing every ray would release. The bit costs one byte per grid cell; \code{voxel3d} publishes no free space.

\noindent\textbf{Scan-counted windows depend on the input rate.} With \code{window\_mode} \code{scans} a window is \code{layer\_interval} integrated messages, so its length in seconds, and the period that \code{period\_windows} stands for, follow the rate of messages the node actually integrates; messages lost on a best-effort link, dropped for missing TF or skipped by an overloaded node stretch every window. In the synthetic ROS check, withholding 40\,\% of the scans turns the tested door cells static (at least 95\,\%, none periodic) with scan windows (\code{grid2d}), while time windows keep the door periodic in \code{grid2d} and out of the static map in \code{voxel3d}; the continuous integration (CI) asserts all three. Time windows trade this for rate-dependent evidence: a window with few messages is less likely to see a hit, so a sensor rate that varies with the phase of a cycle can itself look periodic, outside the null of the test. Once a second the node publishes on \code{/diagnostics} the input rate, the lost share (estimated per sensor frame from stamp gaps, valid while about a fifth of consecutive messages arrive back to back; above about 80\,\% loss, set \code{expected\_scan\_rate\_hz}), TF failures, the window duration and the period in seconds. It warns on lossy or jittery scan windows, empty or thin time windows, zero or stalled stamps and a stalled simulation clock, names a failing TF lookup, and turns ERROR when input or integration stops; Table~\ref{tab:node} gives the exact levels and the check behind each. With time windows the period is \code{period\_windows} $\times$ \code{window\_period\_s} seconds; a deployment should measure the rates on the robot, keep a window long enough to hold several messages, and choose \code{period\_windows} from the period it wants to detect. The experiments integrate every message and are unaffected.

\noindent\textbf{Design trade-offs.} Three simplifications are deliberate. A single global \code{survival\_decay} replaces the per-cell survival posterior of \citet{rosen2016persistence} and the learned transition rates of \citet{tipaldi2013lifelong} and \citet{saarinen2012imac}; E3 shows that, once paired with hysteresis, one uniform rate already yields F1 1.000 at both $\lambda{=}0.90$ and $1.0$, but a scene with sharply heterogeneous per-cell dynamics is untested. The flat hash trades memory scaling for simplicity, as above. And two backends behind an \code{if}/\code{else} factory is the right amount of mechanism for two, but a third backend would argue for a registry such as \code{pluginlib} \citep{ros2pluginlib}; this is a design judgement, not a measured result.

\noindent\textbf{When not to use \sname.} It is not a substitute for SLAM: it estimates no pose and closes no loops, so a deployment without an external localizer publishing the \code{map}$\to$sensor transform has no path to a map. It is not multi-session mapping: comparing Monday's map with Friday's or replaying a past session needs the versioning of LT-mapper or \citet{yang2025lifelong3d}. It has no object-level reasoning, unlike the object-level change reasoning of Khronos \citep{schmid2024khronos}. And it does not discover periods: where the relevant cycles are unknown or are not harmonics of one base period, FreMEn's selection among candidate periods \citep{krajnik2017fremen} or warped hypertime \citep{krajnik2019warped} is the better tool. Within those bounds---one continuous session behind an external localizer, at the raw cell level, in 2D or 3D---it is the intended fit.

\noindent\textbf{Limitations of the real-data evidence.}
\begin{itemize}
  \item \emph{Provisional defaults.} The pair $(0.20,0.70,0.01,0.01)$ is the result of the calibration rule with a failed quality gate waived; the pre-registration is not frozen (Section~\ref{sec:calib}). It is valid for one-second windows and the 2D sensor and resolutions measured.
  \item \emph{The 3D pair is not calibrated.} No 3D measurement passed the rule, the Keble~02 clutter class is mostly not walking people, and the 2D pair is used in 3D. Every 3D row of Section~\ref{sec:realeval} carries this limit.
  \item \emph{Realised rates above nominal.} The per-cell false-Static rates on real clutter are above $\alpha$, for reasons that we did not separate (above). No guarantee of this paper is stated for real windows.
  \item \emph{Periodic is not validated on real data.} No public sequence has a door with a logged schedule. The veto is on in the primary runs and its effect is measured only as on against off; whether it finds doors, or labels slow clutter Periodic, is shown only on synthetic streams (E5).
  \item \emph{Memory.} At 0.1~m with the veto on, \PtFailAll{} runs ended out of memory at the 9~GB limit of the harness (Keble~03 and the semi-indoor KTH sequence); the veto-off runs finished. A Fourier record is allocated for every cell touched with the veto on (Section~\ref{subsec:classify}), the likely cause. The probe committed in the first amendment of the pre-registration measured the cost on the first ten frames of one Boreas session (0.2~m voxels, ranges 3 to 50~m, sequential-test arm): on \PtProbeCells{} cells the peak memory was \PtProbeOff~MB with the veto off against \PtProbeOn~MB with it on, more than five times. Memory grows with the cells touched; Undecided cells are kept and nothing is forgotten out of view, so memory is unbounded over a lifelong run. We did not extend the probe to a veto-on and veto-off table of the full runs.
  \item \emph{Single pass and a pair that is not calibrated.} The KTH sequences are one pass, so they say little about lifelong behaviour and no row is a removal score. The OctoMap and ELite rows apply their increments once per touched window and are not the published methods; no arm for MTD-Map was built.
  \item \emph{No truth in Boreas; one day in Spires; people and furniture mixed in LILocBench.} The Boreas comparison is agreement between sessions, not accuracy. The test sequences of LILocBench come from the same office and robot as the calibration sequences.
  \item \emph{Consuming the map.} Only Static is drawn $100$ on the 2D \code{/map}. A Transient cell and a cell whose last observation was a hit read $50$, Periodic reads $75$ and Unknown reads $-1$ (Section~\ref{subsec:classify}); \code{voxel3d} publishes Static voxel centres only. On LILocBench wall runs a Static cell appears after a median of \PtWallMedSprt{} windows (upper decile \PtWallNinetySprt{}; one window is one second), and \PtWallNotSprt\,\% of the wall-run cells are not Static at the end. On a single pass, up to \PtSpBUndSprt\,\% of the non-ground structure of a Spires sequence ends Undecided. Do not use the STRATA map as the only source of obstacles: a planner that reads only the value $100$ sees a wall late and may not see part of it. Nav2 reads these values through \code{StaticLayer::interpretValue} (we checked the source of the Humble branch): with the default \code{trinary\_costmap} true and \code{lethal\_cost\_threshold} $100$, only $100$ is lethal, and $50$ and $75$ read as free space; with \code{trinary\_costmap} false they scale to partial costs, and a threshold at or below $50$ makes every Transient cell lethal.
  \item \emph{Measured 3D cost of the shipped-on veto.} The veto is on in the shipped 3D parameter file. The committed memory probe above shows more than five times the memory with it on, every run at 0.1~m with the veto on that was started (\PtFailAll{} runs) ran out of memory, and the Spires false reject of non-ground structure is between \PtVetoSpLo{} and \PtVetoSpHi{} times that of the veto-off setting. Turning the veto off removes the Periodic label, which is not validated on real data anyway. We pick no winner and change no default.
  \item \emph{Revisits.} The sequential test waits for evidence. On a single pass part of the structure stays Undecided (up to \PtSpBUndSprt\,\% of the non-ground structure of a Spires sequence), and a lifelong mapper needs revisits that these data do not contain.
\end{itemize}

\noindent\textbf{Limitations of the synthetic evidence.} The synthetic numbers come from a deterministic seeded harness driving hand-authored hit and miss patterns through the engine; the FreMEn grid of \citet{krajnik2016persistent}, ELite, LT-mapper and \citet{berrio2021longterm} report long-term real-world evidence of a kind that this paper does not. E1--E4 are single-seed and carry no dispersion estimate; only E5 to E7 are multi-seed. No FreMEn model is run on the same streams, so this paper does not show that the periodic test, whose false-alarm bound holds for iid clutter, labels periodic cells better than FreMEn's amplitude-ranked component selection. The synthetic evidence establishes a transparent state machine, not a reliable scene classifier: aperiodic cells of moderate occupancy end Static in both arms, low-duty doors are lost to pruning in the legacy arm under the E2 parameters, and at the shipped period correlated clutter is labelled Periodic (below). \EfourLimit{} The ROS node has not been run on a robot or on a recorded bag, and it was not in the loop of the real-data runs of Section~\ref{sec:realeval} either, which come from the offline harness with reference poses: TF latency, transport loss, localiser error and stamp offsets enter none of those numbers. The evidence for the node is the unit tests of its ROS-free helpers and the synthetic scenarios of Table~\ref{tab:node}, which continuous integration runs on ROS~2 Humble only, in one container image; the zero-stamp rule, the no-window-closing warning and the sensor-frame cap and expiry have no dedicated check. The saved map was loaded by \code{nav2\_map\_server} in that Humble job only; no other distribution is in the continuous integration, and the node does not verify a saved pair itself. The engine models single-session persistence only, forgets only what it re-observes (Remark~\ref{rem:fov}), and loses low-duty-cycle periodic cells to the prune/maturity race of Proposition~\ref{prop:race}. The periodicity test has limits of its own. What is proved (Propositions~\ref{prop:chernoff} and~\ref{prop:spend}) is a per-history bound under an iid null and occupancy-independent touches: at the shipped level, a cell that is never pruned is labelled Periodic at some window of the run with probability at most 0.2. The 0.01 target is a measurement: at most 2 of 2000 clutter cells within 1024 windows on held-out seeds (E5, legacy arm; \SqEfiveWorst{} in the sprt arm), and for pruned clutter the proved bound grows with the number of re-created histories. The Wilson limits quoted with it are computed per configuration and are not adjusted for the 36 held-out clutter configurations examined. Temporally correlated clutter violates the null, and at the shipped $T{=}24$ the test labels most slowly switching cells Periodic (1908 of 2000 in E5). Spending costs detection delay: a noiseless 50\%-duty door with $T{=}8$ needs 25 windows instead of 15, and one with 10\% flipped windows 48 instead of 26. Finally, the dominant labelling error is not periodic at all. The graduation rule labels a cell Static when it is occupied in more than roughly $m^\dagger$ of its touched windows (Remark~\ref{rem:drift}; 0.354 with the v0.1 defaults), so it cannot separate random clutter from a noisy wall of similar occupancy: E3 scores Bernoulli(0.6) cells as walls and E5 scores Bernoulli(0.5) cells as clutter, and with the v0.1 defaults 1998 and 1974 of 2000 such cells are Static after 256 windows (E6). Version 0.2 replaces those defaults by the sequential test; between $m_0$ and $m_1$ the test promises nothing, and E6 measures what it does there (Section~\ref{subsec:sprtsynth}). The natural next steps follow directly: a null that allows temporal correlation, for example by testing the harmonic against a local noise floor rather than against white noise, and an anytime-valid test that also covers re-created histories and correlated windows; a FreMEn baseline on the same synthetic streams; a second statistic whose sign is stable across datasets; a pair that passes the quality gate, with revisit-rich data in 3D; a recording of a door with a logged schedule, which would be the first real-data test of Periodic; field deployment on a 2D wheeled platform and a 3D-LiDAR platform; per-cell learned decay; exempting recently active cells from pruning, or feeding a running amplitude estimate into \eqref{eq:prune}; and relaxing untouched cells toward the prior on a tick basis, without changing the touched-cell path that E1--E4 characterise.
